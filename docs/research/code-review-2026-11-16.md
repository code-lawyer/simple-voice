## Standards

1. **P1：草稿读取可阻塞取消。** `worker_recognizer.cpp` 的 `AcceptAudio` 原先持有文字缓存共用的锁，等待最长 15 秒的 RPC；UI 的 `OnPartial` 调用 `Partial()` 时可能等同一把锁，违背 DESIGN 的 Esc 取消行为及专业发行计划的快速取消要求。已分开 RPC 锁与缓存锁，只有短暂的字符串交换持有缓存锁。
2. **P2：发布验证指南滞后。** 开发指南仍列四组 CTest、三份 PE 及 rc.5 证据；实际新增了模型 worker 测试与第四个产品二进制。已更新为五组、四份 PE 与 rc.6 证据，并同步 DESIGN 的六个设置标签页和状态反馈规则。

代码异味属于判断项：没有发现值得在此冲刺期间引入额外重构的项目。固定型号分支符合三个预设的明确范围，不据此引入通用模型框架。

Standards 共 2 项；本轴最严重的是 UI 取消被推理阻塞。

## Spec

1. **P1：下载后丢失设置，旧任务可能覆盖新选择。** PRODUCT 要求“成功验证并保存才改变当前选择”，并保留用户“明确填写的专名提示”。原下载只接收型号，完成后从旧设置重新构建候选，丢失同次修改的闲置释放和专名。修复保留完整请求，任务进行期间拒绝并行激活，界面同步禁用重复操作。
2. **P1：共用草稿缺失会反复下载。** PRODUCT 要求“缺少模型时自动下载、校验并试加载”。原模型专用下载只补定稿文件，但验证还需要共用草稿，下载完成又进入同一下载入口。修复将必需草稿纳入预设包，支持数据目录内的完整组合；下载完成只验证一次，失败返回可处理错误。
3. **P1：隔离推理仍可拖住主界面。** 发布说明承诺“加载崩溃或超时不会拖垮主界面”。除 Standards 中的共用锁，原重置和停录线程等待也在 UI 上。修复把重置放到采音线程、停录等待放到定稿线程，使取消消息可被处理。
4. **P2：试用绕过模型延期和错误确认约束。** PRODUCT 要求切换“留到下一次录音”，未知或异常内容“需要补全核对”。原试用忽略待切换模型，且未拦截带错误的待确认内容。修复在开始试用前处理待切换方案，并复用错误/未知文本确认门槛。
5. **P2：旧备份可能间接改变模型选择。** PRODUCT 规定备份“不包含…模型选择”；旧 preferences.ini 的 `chinese_only` 会在缺少独立模型设置时参与下次启动迁移。修复在恢复前持久化当前模型选择，避免恢复旧偏好后重选模型。
6. **P1：GUI 启动下载时继承了不兼容的 PowerShell 模块路径。** 自动下载要求可实际执行；普通用户令牌下复现 `Get-FileHash` 不可用，而手动 shell 会调整环境。正式下载脚本改为显式导入当前 PowerShell 运行时的系统模块，并补充无效 PSModulePath 的真实脚本回归；失败信息不再伪装为仍在进行。

未发现要求新增功能的范围蔓延。签名、真人验收和远程 CI 分别核验，不以本机测试通过冒充全部发行条件完成。

Spec 共 6 项；本轴最严重的是下载状态错误与不可及时取消的推理等待。

## 验证与产物

用户追加要求后的最终清理删除了未使用的路径帮助函数和旧中文模型状态字段，主引擎不再重复编译仅 worker 需要的直接 Sherpa 实现。过时的初期规格/计划和本地过程笔记归档到被忽略的本地目录，现行产品规则、许可、基准数据和发行证据保留。发行 ZIP 只带当前使用说明、许可、当前发行/审查证据和 README 使用的截图；开发与设计文档通过仓库链接查看，不再捆绑历次冲刺记录。

发布前检查发现旧远程 CI 在显示 SDK 传输完成后耗尽作业时限。依赖脚本绑定 Windows 系统 curl/tar 并增加阶段时间后，远端明确完成下载和 SHA 校验，停在系统 tar 解压阶段；其内部根因仍未确定。CI 的 SDK 步骤设 5 分钟时限，避免静默占用整个作业，并显式使用 runner 已安装的 7-Zip 分两层解包，继续校验原始归档和安装文件。普通用户默认路径仍使用系统 tar，不要求额外安装解压软件。远端完整构建、回归和打包状态以该提交的 Actions 记录为准。

最终命令、通过数量和候选包结果统一记录在 [rc.6 验证记录](../releases/v0.2.0-rc.6-validation.md)。本轮原生 UI 每套 83 项断言通过；截图在 `build-review/public-sprint/review-ui-{titanium,daylight,deep-space}/`。新增 worker 回归先在旧锁实现失败，再在修复后通过，日志为 `review-worker-before.log` 和 `review-worker-after.log`。

现有真实语音样本只证明对应音频的模型运行及文字保留，不构成竞品准确率排名。正式发行仍需既有真人、签名与环境矩阵验收。
