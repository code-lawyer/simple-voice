# 本地 IPC 的权限与兼容约定

引擎在独立进程运行，TSF DLL 由 Windows 加载到各个输入应用中。本地管道承载语音控制、
状态、光标位置和确认后的文本。协议 v2 在保留跨应用确认的同时，对连接双方和控制时机进行检查。

## 连接与权限

- 管道为 `\\.\pipe\SimpleVoice.v2.<登录 SID>`，单实例锁为
  `Local\SimpleVoice.v2.<登录 SID>`。使用显式 DACL，只向本次 Windows 登录的 SID 授权；
  禁止远程管道客户端。安全描述符或身份查询失败时拒绝连接，不退回宽松权限。
- 双方从 Windows 管道 API 获取对端 PID，核对用户 SID、登录 SID 和会话 ID，拒绝
  AppContainer。连接期间持有进程句柄，避免把复用的 PID 当成原来的进程。
- 客户端还核对服务器映像与 TSF DLL 同目录的 `voiceime_engine.exe` 为同一个文件。
  引擎要求客户端先发送 `ClientHello`，提供自己进程的 `VoiceImeTsfHost` 窗口；核对窗口
  所有者及窗口类所属模块与引擎同目录的 `voiceime_tsf.dll` 为同一个文件。
- 握手限时 3 秒。引擎验证完成后先连续发送 `ServerReady` 和初始 `Phase`，再允许该连接
  接收广播。未握手、借用其他进程窗口、未知类型和错误方向的消息都会被拒绝。
- 新动作要求经过验证的客户端进程当前位于前台。已有插入操作的回执仍按原客户端及
  请求号关联，避免焦点切换导致已经完成的写入无法确认。
- 开发版增加无正文的 `PreloadModel`（21）。TSF 在前台键盘焦点和管道握手均就绪后通知一次。引擎沿用前台检查，空闲时后台准备模型，录音阶段和话轮状态序号均不改变。部署沿用 DLL 与引擎成套更新的约定。
- rc.12 的拼音连接用 `PinyinHello`（22）单独握手，双向核对进程、模块和窗口身份。每个连接拥有独立的 Rime 组合会话，同一登录会话中的引擎统一打开用户词库。按键、清除和候选回复（23–25）只在该连接传输。Windows 成功写入后发空回执（26），引擎按该连接最后一次提交的词结算一次，切换前台应用不影响这次回执。

这里的信任对象是加载了本安装 DLL 的桌面宿主进程。它可以阻止普通陌生管道客户端直接
开麦、取消或领取待确认文本，**不构成对同账号恶意代码的完整隔离**：恶意代码主动加载或
冒充受信任宿主、注入该进程、控制其窗口，或替换可写安装文件，不在这一边界能保证的范围内。
这也不是代码签名验证。跨权限应用的兼容性仍需另行验收，无法验证的对端会被拒绝。

## 话轮与确认

`Phase` 带有非零的 64 位状态序号。话轮、阶段或待确认文本改变时序号递增；监听中的草稿
变化不会令停止按键失效。`StartListen`、`Enter`、`Cancel` 必须带上客户端已收到的序号。

rc.7 新增阶段值 `5`：录音达到上限，收音已停止但尚未校准；`0`–`4` 含义不变。客户端在
阶段 `5` 仍拦截语音确认/取消键，Enter 或语音快捷键只请求校准，不能写入草稿。与到时竞态
的同话轮停止请求可继续生效；定稿完成后旧请求仍不能确认后来产生的预览。升级须同时更新
DLL 与引擎，旧 DLL 不识别新增阶段；按安装流程注销再登录后刷新。

迟到的 Enter 不能把后来产生或编辑的预览直接提交。为保留正常的快速操作，同一客户端
紧跟已接受 Start 的 Esc、停止按键可在阶段回复之前生效；同一话轮的 Esc 也能越过结束识别
的竞态取消。旧话轮的命令不能操作新话轮。开发版在冷启动缓冲期间检查原客户端是否仍连接且位于前台，失去前台或断开时终止这次收音并清理缓冲。用户已经明确停录后，模型可以继续校准，通过当前前台客户端确认预览。等待上一段识别结束的开始请求仍在实际开始前重新核对前台。

用户可以在应用 A 开始录音，切到应用 B 查看并确认。B 必须通过相同的宿主验证、成为前台
进程并取得当前状态，文本只发给实际确认的连接。状态序号用于关联命令，不是秘密凭据。

## 快捷键与升级

TSF 激活时读取一次快捷键配置。引擎成功保存快捷键后广播 `SimpleVoice.HotkeyChanged.v2`，
各宿主收到通知后重新读取。按键预检、正式按下及 Shift 释放只访问缓存，不读取文件。
手动编辑配置文件需重新激活输入法后生效；缓存刷新失败沿用配置解析器的默认快捷键规则。

协议 v2 与旧管道隔离，不能只替换 DLL 或只替换引擎。升级时使用包含两者的新安装目录，
按既有安装流程重新注册并注销 Windows 后登录，防止应用继续加载旧 DLL。个人数据位置和
TSF GUID 保持既有约定。已退休的消息编号不复用：3、4、5、6、7、8、13。

## 验证与实现参考

常规四组 CTest 包含管道 ACL/对端身份、未握手与借用窗口拒绝、后台与过期命令拒绝、
跨进程合法确认、快速取消/停止、握手与阶段切换并发、模型准备后重新授权、快捷键缓存
与变更通知。引擎集成使用真实管道和进程，采音为合成输入，前台 PID 为编译期测试宿主
注入的夹具；生产程序不接受该夹具。TSF 集成使用真实 Windows TSF 的隔离宿主。

这些测试须在普通桌面用户令牌下运行；受限令牌可能被新身份检查或 TSF 拒绝。
它们不代替已安装版、真人麦克风或跨权限应用验收。构建和命令见 [开发与验证](development.md)。

Windows API 依据：[命名管道安全与访问权限](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)、
[GetNamedPipeServerProcessId](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeserverprocessid)、
