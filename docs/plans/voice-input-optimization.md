# 轻音输入法语音优化施工方案

2026-11-21 · Windows 桌面版 · 发布基线 `v0.2.0-rc.9`。下文标明本地已实现的改动，以及之后每次要交付的产品行为。

## 一、切换到轻音时预加载当前模型　已实现于本地候选

过去，切换输入法会连接主引擎，Qwen 则要等第一次按语音键才加载。本机上一轮测得新进程加载中位数为 3.49 秒。现在把这段工作提前到用户选中轻音时。启动一次 Qwen 后，模型进程工作集约 1.23 GiB，常用普通话短句的 SenseVoice 约 0.51 GiB。[本机测量](../research/voice-runtime-2026-11-21.md)

- **输入法端。** Windows 选中轻音的语言配置，或把键盘焦点交还给已选中轻音的应用时，前台客户端向主引擎请求预加载。客户端核对轻音自己的语言配置标识，切入时若引擎尚在启动，就在连接完成后补发。同一次切入中收到多个通知只处理一次。[轻音 TSF 实现](../../src/tsf_service.cpp) · [微软语言配置切换通知](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfactivelanguageprofilenotifysink-onactivated) · [微软键盘焦点通知](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfkeyeventsink-onsetfocus)
- **引擎端。** 主引擎核对前台客户端，在后台加载用户选中的本地模型。多个应用共用一个模型进程。正在加载时按语音键会立即启动采音，复用同一次加载。单纯切入保持空闲，麦克风只在主动开始语音后开启。模型驻留时间由闲置释放设置决定。[模型准备与录音入口](../../src/engine_main.cpp)
- **设置。** 「设置 → 本地模型 → 切换到轻音时预加载语音模型」默认开启，只用拼音时可以关闭。它和「闲置 5 分钟后释放模型」各自保存。关闭闲置释放，模型就绪后可以持续驻留。预加载选项独立存储，旧版的模型路径、专名和闲置选择继续用原文件。[本地模型设置页](../../src/preferences_view.cpp)

本机用真实 Qwen 权重连续启动三个新模型进程。从客户端发出预加载请求到模型就绪，三轮为 3.47、3.67、3.71 秒。就绪后首次发送语音指令，到引擎返回监听状态，分别为 7.7、6.8、10.6 毫秒。这里使用合成采音，实体麦克风首帧和首字显示还需各自计时。[隔离引擎复现实例](../../tools/engine_integration.cpp)

预加载把准备权重的时间移到切入之后。用户在模型就绪前就按键开口，走下面的冷启动收音流程。

## 二、按语音键就收音，保住第一句话　已实现于本地候选

语音热键和设置页的「开始试用」共用录音入口。收到明确的开始指令，引擎即启动采集线程，模型准备与打开麦克风并行。第一帧到达后，若模型还在加载，浮层显示「正在收音 · 模型准备中」。[引擎实现](../../src/engine_main.cpp)

1. **模型未就绪。** 本次录音拥有一条内存队列，保存 16 kHz 单声道 PCM16。模型就绪后由同一解码线程按顺序处理积压与新采样。队列最多容纳 192,000 个待处理采样，净载荷 375 KiB。自 rc.11 起，热启动同样使用这条队列。[语音缓冲](../../src/capture_buffer.hpp)
2. **先说完。** 首次 Enter 或再次按语音键会立即发起停录。采音线程停止 Windows 音频流，取出设备已交付的数据和重采样末尾，模型稍后就绪再出预览。停录后可以切换应用，最终文字只在新的确认操作后写入。[Windows 音频流停止行为](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-stop)
3. **缓冲满或设备断开。** 停止收音并提示原因，保留已有采样，等用户按 Enter 请求定稿。正常识别时整段录音上限仍是 10 分钟。模型未就绪且仍在收音时，原输入应用失去前台或断开连接，会丢弃这一段。Esc 会清理本次缓冲并隔离迟到回调。
4. **首批验收。** 同一段短音频分别在模型未加载和已准备时送入引擎，比对采样数、最终文字和手动确认。实体麦克风首帧、蓝牙设备和自然口述仍需单独体验。[端到端录音用例](../../tools/engine_integration.cpp)

本机真实 Qwen 回放了 5.592 秒普通话（89,472 个采样）和 1.65 秒英语（26,400 个采样），各做一次冷启动和一次热启动。两段冷启动都在模型就绪前停录，各自的最终文字与热启动逐字相同。普通话输出为「開放時間：早上9點至下午5點。」，英语为「Hello, world.」。冷启动从发出语音指令到观测到首批模拟采样分别为 9.2 和 10.4 毫秒。这两句用于验证收音和定稿的衔接。[项目语料说明](../../tools/asr-benchmark/corpus.json)

首批本地构建通过了单元、引擎、Windows 输入服务、浮层和模型进程五组回归。

## 三、让草稿先出来，降低日常内存　已实现于 rc.10 本机试用版

- **草稿和定稿分别就绪。** 流式 Zipformer 加载完成后就接收已录音频并更新浮层，Qwen 在本进程的后台线程加载。设置页手动切换仍以完整模型加载成功为准。Qwen 模式下，一个共享权重的临时识别流最多读取最初两秒，尝试提前给出第一个汉字。常规流接手后按原来的上下文继续识别。[识别器](../../src/sherpa_recognizer.cpp) · [模型工作进程](../../src/model_worker_main.cpp)
- **让用户直接按场景选择。** 在现有模型页明确给出「日常普通话」的 SenseVoiceSmall 和「中英混说、技术专名」的 Qwen。两者共用流式草稿，常态只驻留所选定稿模型。上轮同一批普通话中，两者分别错 59 和 58 个字符，定稿计算中位数为 183 和 999 毫秒。已有用户的选择继续生效。[模型设置](../../src/model_settings.cpp) · [对照结果](../research/voice-runtime-2026-11-21.md)
- **定稿后释放临时内存。** Qwen 的 CPU 会话已关闭内存池，离线解码线程复用音频转换缓冲，并在推理前释放已消费的 PCM。保留用户选择的闲置策略。短句、长段和连续使用的实测结果见本次试用版记录。[rc.10 本机实测](../releases/v0.2.0-rc.10-validation.md)

### rc.11 的连续口述和停录响应

rc.10 的首字优化只覆盖开口后的最初两秒。已安装的双语 Zipformer 编码器导出的 `decode_chunk_len` 为 32，同一批 28 段录音中，句中草稿更新间隔的中位数仍是 320 毫秒。下一版优先改善说到半句时文字跟上来的速度。[rc.10 本机对照](../releases/v0.2.0-rc.10-validation.md)

1. **热启动也独立收音。** 采音线程只向有界队列写入。解码线程独立取音，停录时排完已接收的采样再定稿，取消时丢弃本次队列。[采音入口](../../src/engine_main.cpp)
2. **让句中草稿提前。** 在同一批 28 段录音中，原生 160 毫秒 X-ASR 的正确文字较 rc.10 晚 220 毫秒。试用版采用原双语模型，把两条辅助流分别错开 120、240 毫秒，共享编码器权重。提前显示的短后缀须能接上已有文字，数字和英文片段需要第二条流佐证。[草稿选择](../../src/live_draft.hpp) · [逐位置对照](../releases/v0.2.0-rc.11-validation.md)
3. **提前校准自然停顿。** Qwen 在安静尾部提前计算，短停顿后继续说则保留原音频重新识别。六秒以上的片段遇到至少 600 毫秒的安静间隔后，只有主草稿流识别出两个时间戳落在续说部分的词元，才会把前段单独定稿。尾部只有碰撞声、证据不足或预计算返回空时，仍可用完整音频校准。[停顿检测](../../src/audio_segments.hpp) · [定稿线程](../../src/sherpa_recognizer.cpp)

## 四、针对短词、数字和专名改识别

- **减少截断。** 长口述目前在第 10–15 秒里选择能量最低的 20 毫秒切开。改为优先寻找一段连续停顿，在停顿中间切分，连续说话才保留兜底切点。保留切点两侧全部采样，重点看跨段的报号和英文专名。[分段算法](../../src/audio_segments.hpp)
- **控制短词误补。** 当前短词首次定稿为空时会补 160 毫秒静音再试，实测既救回过正确数字，也把 “zero” 猜成过 “system”。下一步根据有效人声持续时间决定是否重试，给疑似纯噪声返回空结果。单独比较漏字和错出字，避免把两种错误抵消。[短词处理](../../src/sherpa_recognizer.cpp)
- **给专名一个明确入口。** 复用 Qwen 已有的显式专名提示。在词语页增加「加入语音专名」操作，让用户选中姓名或项目名、核对后加入提示列表。普通拼音选词继续只影响拼音偏好，语音定稿也不强制替换相似词。[模型提示设置](../../src/model_settings.hpp)

## 交付时怎样判断有效

每批先交付可运行的候选程序，再附同机结果。首批看切换后首次语音能否复用模型、立即开口是否保住首尾、取消后是否还会出字。第二批看停说到最终预览的时间、每百字人工修改数和连续口述 50 轮后的内存。普通话、短词、数字与中英专名分开评分。

冷启动首帧 P95 建议目标为 300 毫秒，普通话盲测字符错误率目标为相对下降 15%，独立短词集整词正确率目标为提高 10 个百分点。用相同公开录音与 CapsWriter-Offline 做本地对照，Win+H 单列联网参照。跨应用拼音学习漏记另立修复项。[CapsWriter 官方项目](https://github.com/HaujetZhao/CapsWriter-Offline/blob/v2.6/readme.md) · [微软语音键入说明](https://support.microsoft.com/zh-cn/accessibility/windows/use-voice-typing-to-talk-instead-of-type-on-your-pc)
