# rc.13 短句定稿与七天词语审阅验收

2026 年 11 月 23 日，在同一台配有 Intel Core Ultra 7 255H 的 Windows x64 电脑上，将 rc.12 与本轮试用版作对照。使用相同的双语流式模型、Qwen3-ASR 0.6B INT8 权重和 CPU 配置。

## 连续使用时的定稿等待

隔离引擎按实时速度从公开样本回放 16 kHz 单声道录音。每个会话先完成一次识别，随后在同一进程内重播相同录音。最后一包音频到达引擎后发送停录键，等候待确认状态，并读取原生浮层的可见状态和文字。再次按 Enter 后，测试核对发给宿主的文字与屏上文案一致。下表计入热机轮次，包含浮层状态更新，计时精度到窗口状态可读。实体键盘、麦克风和显示面板的物理延时另行验收。[回放入口](../../tools/engine_integration.cpp) · [逐次数据](v0.2.0-rc.13/warm-latency.csv)

| 停录到浮层可核对，中位数 | rc.12 | rc.13，收集关闭 | rc.13，收集开启 |
| --- | ---: | ---: | ---: |
| 报开放时间，5.12 秒，截去自然尾音 | 1,239 毫秒 | 773 毫秒 | 747 毫秒 |
| 连续普通话，5.61 秒，录音结束即停 | 1,098 毫秒 | 987 毫秒 | 859 毫秒 |
| 同一句开放时间，5.59 秒，保留自然尾音 | 654 毫秒 | 383 毫秒 | 371 毫秒 |
| 三条等权合计，中位数 | 1,024 毫秒 | 759 毫秒 | 747 毫秒 |
| 三条等权合计，P95 | 1,657 毫秒 | 1,219 毫秒 | 933 毫秒 |

每格八次热机回放，分两轮连续测量，每轮四次并轮换新旧版本先后。合计行每个条件有 24 次，P95 取从小到大第 23 个值。两轮之间把语言预填和提前分析的适用范围收至六秒内，表中三条录音始终走同一条短句路径。运行负载会波动，收集开启组的较低数值不能单独归因为开启收集。

按 20 毫秒帧的音量和峰值估算，从末个有声音频帧到按停录，三段分别还有约 0、172、452 毫秒。把这段时间也算上，报时两种结尾在新版分别约为 773 和 835 毫秒，连续普通话约为 1,159 毫秒。说完可以直接按键，专门等停顿会增加实际等待。连续普通话的定稿文本相同，报时的九点至五点含义保留，数字和繁简写法随样本及版本有所变化。[声学判断](../../src/audio_segments.hpp)

已有 Qwen 专名时另外回放截尾报时两次，旧版中位数为 1,387 毫秒，新版为 944 毫秒，两版都保留早上九点至下午五点。该场景继续使用自动语言识别，样本量不足以估计专名设置的速度影响。

另一个样本在中文报时后停顿，再补说 “Hello World”。两版五次热机回放均保留英文尾句。这个样本新版更慢，中位数从 1,005 毫秒升到 1,408 毫秒。旧版单次范围 546–1,275 毫秒，新版 508–1,494 毫秒。这项结果单列于三条普通话之外，原因尚未确定。

## 定稿内容

另用相同模型进程分别回放 38 段，包括项目的 16 段中英诊断样本、20 段 FLEURS 普通话真人录音及 2 段停顿后接着说的组合录音。37 段的最终文字逐字相同，另一段把报时的「9 點、5 點」写成「九點、五點」。普通话参考稿归一化后共 667 个字符，两版的字符编辑距离都是 47。地名「基希讷乌」两版都未写对。项目的英语 “nine” 经短音频重试后仍识别为 “Nine.”，两段中英组合录音都保留了停顿后的完整尾句。[逐段核对表](v0.2.0-rc.13/recognition-quality.csv) · [项目诊断样本来源](../../tools/asr-benchmark/corpus.json) · [Google FLEURS](https://huggingface.co/datasets/google/fleurs)

## 最近七天

端到端测试从原生设置打开审阅页，确认两个词同时进入个人拼音词库，只有单独勾选的词出现在 Qwen3 专名中。语音样例先将 Cortex 改为 Codex，数据库留下实际写入的 Codex、一次使用及可解释原因。测试还经过取消、写入被拒、练习及重复成功回执。[引擎回归](../../tools/engine_integration.cpp)

Windows TSF 集成测试通过真实文本服务与测试文档写入拼音。六次成功选择分别重复发送回执，累积为六次。预览、设置和审阅窗口可以正常拼音编辑，内部输入不会多计成正文。写入前取消的预览不会贡献最终语音记录。[TSF 回归](../../tools/tsf_integration.cpp)

词库测试使用可控时钟和独立 SQLite 数据库，覆盖七天边界、再次使用不续期旧次数、语音拼音合并、暂停、清空、备份排除短例和数据库暂时被占用。两个连接共用同一临时库时，旧采集任务在另一个连接清空或暂停后不能写回。两次拼音和一次改过字的语音合为一项「轻音输入法」，显示三次、两个来源和手动改字原因。标点、大小写、数字格式及缺少共同词的多词草稿另作对照，避免把整句里的普通词都标成可疑专名。[词库回归](../../tests/word_review_test.cpp)

模拟模型设置文件暂时无法写入时，已确认的词先进入个人拼音词库，语音专名请求保留在本机。重新启动后，只有勾选的专名被补写，并且只补写一次。

最终 Release 构建通过全部五组 CTest，耗时 95.53 秒，包括 102 项单元测试、1,222 项隔离引擎检查、270 项真实 Windows TSF 检查，以及候选浮层和模型进程回归。三套皮肤各通过 143 项原生界面检查。截图采用测试词语，首次开启收集时列表为空。[审阅窗口实图](v0.2.0-rc.13/weekly-review.png)

## 复测范围

有模型和开发构建时，用 `voiceime_engine_integration.exe <测试目录> --cold-capture-real <录音.pcm> --through-load 4` 可先热机，再连测四次。将尾部开关改为 `--through-load-review` 可在独立词库开启收集。使用 `--through-load-hints` 可测试预先设置了语音专名的场景。

试用包面向 Windows Intel/AMD x64。日常麦克风、在浏览器或 Codex 中现场输入、跨系统版本升级与重启仍待真人验收。
