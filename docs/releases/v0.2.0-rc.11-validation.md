# rc.11 本机语音验收

2026-11-21，Windows x64，Intel Core Ultra 7 255H，CPU 推理。对照为本机 rc.10。两版共用相同的双语草稿权重、Qwen3-ASR 0.6B INT8、CPU 配置和公开录音。

## 连续说话的草稿

20 段 FLEURS 普通话和 8 段项目中英文录音以每包 20 毫秒输入真实模型进程。对齐参考文本中的连续片段，按汉字、完整英文词和数字串计数。只比较两版都识别正确、从此保留、在两版中都已开口至少两秒的位置。同一段内的多个字有关联。两段没有可比较的句中位置。时间以已交付音频的长度计。[位置对照工具](../../tools/asr-benchmark/compare_live_drafts.py) · [公开语料口径](../../tools/asr-benchmark/corpus.json)

| 28 段回放 | rc.10 | rc.11 |
| --- | ---: | ---: |
| 句中相邻草稿更新间隔，中位数 | 320 ms | 200 ms |
| 命中连续参考片段的稳定字词数 | 648 | 652 |
| 已经显示的文字被撤回或替换的次数 | 1 | 7 |
| 末次草稿的字符编辑距离 / 参考字符数 | 116 / 876 | 113 / 876 |

26 段共有 574 个句中位置，312 个更早、252 个相同、10 个更晚。逐位置中位数提前 120 毫秒，先按录音分别取中位数再汇总为提前 90 毫秒。上述编辑距离包含项目回归参考、合成语音和自然口述，主要用于同机对照。

另在真实 Windows 浮层上以约 8 毫秒间隔读取三段已加载模型的可见文字。从录音指令计时，两版共有 53 个句中位置，稳定出现的中位数提前 93 毫秒。三段各自的中位数是晚 12 毫秒、早 123 毫秒、早 35 毫秒。三段均未观察到已显示的字符被撤回。这次使用音频回放代替实体麦克风。

另试了原生 160 毫秒双语 X-ASR。它的末次草稿编辑距离为 97 / 876，但与 rc.10 共同识别正确的句中位置中位数晚了 220 毫秒。rc.11 继续使用原双语权重，提前显示有上下文支持的短后缀，英文和数字需要两条流佐证。[上游模型说明](https://k2-fsa.github.io/sherpa/onnx/x-asr/index.html)

## 停录到看见 Qwen 定稿

向 Windows 引擎按实时速度回放公开 PCM，走正式的语音控制消息、识别进程和预览浮层。每个样本先冷启动，再在同一进程热启动。下表是热启动的一次配对，从发出第一次 Enter 到客户端收到「待确认」状态。第二次确认写入的时间单独排除。短句另核对了两版最终文本。[Windows 回放入口](../../tools/engine_integration.cpp)

| 样本 | rc.10 | rc.11 | 定稿内容 |
| --- | ---: | ---: | --- |
| 5.59 秒报开放时间，含自然尾音 | 733 ms | 502 ms | 两版均为「開放時間：早上9點至下午5點。」 |
| 1.65 秒英语，结尾有约 0.75 秒安静 | 413 ms | 3 ms | 两版均为「Hello, world.」 |
| 13.86 秒自然普通话，句中有两处停顿 | 3,153 ms | 771 ms | 两版均保留净空高度、完工年月和通车年月，断句及数字写法有变化 |
| 5.12 秒报开放时间，剪到最后一个字即停 | 1,119 ms | 803 ms | 两版均为「开放时间：早上九点至下午五点。」 |
| 5.61 秒连续讲话，结尾立即停 | 911 ms | 969 ms | 两版逐字相同 |
| 先说英语，停顿后继续说普通话 | 1,335 ms | 1,334 ms | 两版逐字相同，前后两句均保留 |

英语短句的 Qwen 计算在停录前已经完成。没有安静尾音时，Qwen 仍需读取整句。本机把 Qwen 从 4 个线程增加到 6、8 个线程，同一段即时停录样本各做六次，纯定稿计算中位数分别约为 665、725、927 毫秒。试用版保留四线程配置。

## 内存和试用边界

两条辅助草稿流共享权重。Qwen 模式的草稿会话只使用一个推理线程，Qwen 定稿继续使用四个线程。在一段 5.61 秒普通话上，每包 20 毫秒按实时速度送入，各录三轮。模型进程从开始送音到送完最后一包的累计 CPU 时间中位数为 rc.10 的 16.30 秒、rc.11 的 11.77 秒，降低约 28%。累计 CPU 时间会把各个核心的工作时间相加。双线程草稿的中间构建为 26.23 秒。

真实模型进程交替识别上述普通话和英语短句各 25 次，50 次最终输出逐字符合 rc.10 对照。第 50 次完成后，两版工作集均为 1,281.2 MiB，峰值从 1,640.1 MiB 变为 1,640.8 MiB。数字仅涵盖模型工作进程。用户开启的常驻或闲置释放设置继续生效。

音频由测试设备按实时速度送入引擎，实际麦克风、蓝牙链路、个人口音及带噪环境仍以本机试用为准。此版用于本机试用。

五组 CTest 全部通过，覆盖单元、引擎、TSF、浮层和模型进程。注入模型请求阻塞后，已加载模型的采音线程继续接收后续音频包，停录和取消仍然可用。按原项目验收清单回放的 17 项全部通过，含 60 秒长音频、纯静音和独立数字，各项最终文本逐字等于 rc.10。独立短词 “nine” 在两版都返回空，其用例记录该行为。

另对 20 段 FLEURS 人声使用人工参考文本核对 Qwen 定稿。两版有 17 段逐字相同，其余 3 段的字符编辑距离下降。全组从 58 / 667 变为 51 / 667。计分统一简繁、大小写、空格和标点，保留阿拉伯数字与中文数字的书写差别。在 9.18 秒的尾部带杂音样本上，只有声学停顿的早期候选多出了一句话。增加续说词元时间戳验证后，最终版本与 rc.10 均只输出完整的参考原句。
