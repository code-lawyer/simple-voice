# v0.2.0-rc.4 验证记录

Windows 11 26H2 上，Windows Terminal 1.25.3131.0 选中 `rc.3` 的输入法配置后，没有加载轻音 DLL。测试输入 `nihao` 加空格产生六个原始字符。同机普通桌面编辑框使用轻音能输入「你好」，同一终端使用微信输入法也能输入「你好」。

只增加 `GUID_TFCAT_TIPCAP_IMMERSIVESUPPORT` 后，同一终端加载了轻音 DLL，并收到两个汉字「你好」。实验类别随后移除。进程已加载的 DLL 会继续驻留，安装验收需核对全新终端加载的 DLL 路径。

修复注册该类别。Windows Terminal 的应用清单标注完整信任，实际进程令牌也表明它在 AppContainer 之外。输入服务在连接个人词库或引擎前查询令牌，并跳过 AppContainer 和无法确认权限的进程。[Windows 应用输入法要求](https://learn.microsoft.com/en-us/windows/apps/develop/input/input-method-editor-requirements)

MinGW Release 构建通过。用桌面进程令牌执行 CTest，单元、引擎、TSF 和浮层四组均通过（58.95 秒），其中包括 371 项引擎断言和 112 项真实 TSF 断言。

- 全新 Windows 终端进程的 PowerShell 测试中，`rc.3` 收到 `nihao `，安装 `rc.4` 后另一个新进程收到「你好」。模块清单确认后者实际加载 `rc.4` 的 `voiceime_tsf.dll`。已有终端进程仍保留 `rc.3` DLL，完整退出再重开可刷新。
- 系统 COM 注册、生产引擎和安装文件均指向 `rc.4`。任务栏实拍仍显示「中 + 声核」，默认输入法和顺序通过安装前后对比。
- 在 AppContainer 令牌下直接调用生产 DLL 的 `Activate`，返回 `E_ACCESSDENIED`。在桌面令牌下执行真实 TSF 测试通过。
- 两套离线语音模型完成初始化检查。真人麦克风验收继续后置。
