# v0.2.0-rc.3 验证记录

本轮范围为声核图标、Windows 输入法标识、模式同步和托盘刷新；未改识别模型或词库。

## 自动验证

- MinGW Release 构建通过，三个发布二进制均标记为 0.2.0-rc.3。
- CTest **4/4**：unit、engine、tsf、popup；合计 **58.03 秒**。随后安装流程专项修订单独构建、解析和部署验证。
- 真实 TSF 集成 **112 项**，覆盖系统 GUID 注册、品牌名称、模式点击与 Shift、只读保护、语音活动开始/结束的系统状态通知、注销和释放后回调安全，以及七组图标的六种 Windows 必需尺寸与 32 位位深。
- 引擎集成 **371 项**；三套皮肤各 **66 项**界面断言通过。
- 独立视觉审查认可 A 的轮廓、小尺寸清晰度、单色及品牌/模式分离。审查发现的一项状态刷新问题已修复并复审确认。因专用审查角色未提供，使用独立新上下文代理按同一 fallback 合同执行；文档同步也独立完成。

真实 TSF 测试还复现：测试宿主的焦点通知可能不交付，而 `GetFocus` 已指向新文档。因此按钮读取当前可编辑状态，不仅依赖缓存的焦点通知；只读操作同时在执行处核对。

## 安装验证方式与边界

使用独立版本目录和离线模型校验，更新前备份实际账户个人数据。`voiceime_installed_check` 通过系统 COM 注册解析 DLL、读取真实语言栏项目与品牌资源，并确认生产管道服务进程路径及空闲状态。`voiceime_indicator_live_check --show <输出>` 只短暂打开自己的空白输入框、切换本线程输入法、截取任务栏后恢复原配置，不发送文字或启动麦克风。

本机部署具体路径、哈希和截图记录在忽略目录 `build-professional/rc3-*`，不包含在公开源码中。资源预览不是任务栏实拍。真人麦克风、用户浏览器/Codex 输入体验、多显示器/高对比度现场测试继续后置；不能由以上自动检查替代。

## 实际任务栏与安装迁移

真实前台测试窗口确认已激活轻音、加载安装目录中的 DLL，任务栏显示「中 + 声核」。同一窗口的微信输入法对照能显示其品牌图标，确认验证方法有效。验证工具不替换系统项目图标，截图反映实际注册加载结果。

旧注册状态下，正确 ICO、资源编号和兼容类别并不足以让 Shell 从「简体」恢复；更换图标来源和重启 TextInputHost 也没有解决。清理并通过官方 API 刷新配置后恢复。再次写回重复记录未立刻复现，因此只确认旧注册刷新链路存在问题，不断言某个 HKCU 键或单一缓存是唯一根因。

安装现使用机器级 COM、官方类别/profile API、限定本产品 CLSID 的旧 HKCU 迁移和 `EnableLanguageProfile`，不再完整镜像 TIP 元数据。只保留已实现能力，撤回临时 IMMERSIVESUPPORT 声明。提权前传入发起用户 SID，注册程序在任何修改前拒绝不同账号；注销汇总失败并保留可重试状态，安装脚本识别残余 TIP 注册。

最终安装验证通过：完整离线 setup、重复注册、错误 SID 返回 2 且原 COM 路径不变；默认输入法与输入法偏好顺序未变。正常退出空闲的旧引擎后，通过系统 COM 加载最终目录的 DLL，生产管道指向同目录的新版引擎，状态为空闲。新窗口的实际 profile 为轻音且 `caps=0x20000`，品牌实拍见[最终任务栏截图](../design/brand/windows-taskbar.png)。未以关闭用户应用或注销 Windows 的方式强制刷新已有宿主。

独立复审确认安装生命周期的三个问题已修复：提权账号校验、注销错误传播、残余 TIP 的可重试清理。当前生产安装未执行完整卸载，卸载路径完成代码复审；不能把重复安装验证当作卸载验收。
