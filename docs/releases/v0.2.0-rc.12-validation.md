# rc.12 识别与跨应用词库验收

2026-11-21，在同一台 Windows x64 电脑上对比已验收的 rc.11 和 rc.12。两版使用相同的双语草稿权重、本地 Qwen3-ASR 0.6B INT8 和生产代码的 16 kHz 重采样器。

| 同机对照 | rc.11 | rc.12 |
| --- | ---: | ---: |
| 120 段真人单独读英语数字，按数字含义完全匹配 | 55 | 61 |
| 上述录音返回空文字 | 21 | 14 |
| 上述录音输出了错误内容 | 44 | 45 |
| 三个普通话合成声音读短词、单个数字和数字串，保留目标内容 | 28 / 30 | 28 / 30 |
| 三个普通话合成声音各读三个专名，精确匹配目标汉字 | 2 / 9，未填提示 | 5 / 9，填入三个专名 |

真人数字来自项目固定版本的 FSDD，覆盖六位说话者、十个数字，每个组合取第 17 和 31 号录音。只接受单独的正确英语数词、汉字数字或阿拉伯数字，忽略句末标点和英文大小写。另测项目原来的 0.36 秒 “nine”，rc.11 为空，rc.12 得到 “Nine.”。单次回放中这句的模型定稿约从 0.56 秒增到 1.02 秒，无需重试的正常语音仍走原来的解码路径。两组静音、单次脉冲、低噪声和嘶声对照均保持为空。[FSDD 固定版本](https://github.com/Jakobovski/free-spoken-digit-dataset/tree/26eb9aaf76e81b692f806f9140c2d2777410d7a1)

普通话材料使用 Windows 的 Huihui、Kangkang 和 Yaoyao，回放通过真实模型进程。「栖云工坊」由三个声音均错变为两个读对，「沈嘉祺」加提示后仍会写成「沈佳琪」。这组对照同时体现用户启用提示和模型的表现。输入八个英文短词和两段连续报号，两版输出相同。这些合成声音的结果不代表真人口音的准确率。

旧版用两个独立宿主和隔离的新词库复现。第二个宿主拼 `shi`，连续六次选「十」，第一个宿主及重新打开的词库都把「十」排第三。单宿主执行同样操作后「十」升至首位，并能在重启后保留。旧版把 librime 放进每个宿主，两个运行时同时打开同一个 LevelDB 用户库，第二个宿主能给出候选，却不能正常积累这批选择。

项目原有 17 段语音回放全部通过，16 段最终文字与 rc.11 相同，余下一段是修复的 “nine”。20 段 FLEURS 普通话真人公开录音中，18 段定稿逐字相同，一段变化是逗号，一段将「二零零二」写成参考稿中的「2002」。沿用 rc.11 的计分方式，字符编辑距离从 51 / 667 变为 47 / 667，差值来自数字写法。五组 CTest 和原生设置窗口的专名添加、去重检查均通过。

新版沿用原用户库，将独立的 Rime 会话移到轻音引擎。回归启动两个 Windows 应用进程，共用一个隔离的正式引擎实现。第二个应用的六次选择在第一个应用升至首位，引擎重启后仍在首位。手动保存词语的使用计数恰好增加六次。暂停学习期间在第二个应用选择另一个候选，恢复后原排序保留。测试使用隔离数据，未向个人词库添加测试词。[跨应用回归](../../tools/tsf_integration.cpp)

另外复现了升级期间新旧进程同时打开词库的情况。旧版占用词库时，原实现仍接受拼音输入，并触发 LevelDB 自动修复，改变了 CURRENT 指向的文件。新版先检查旧文件锁，遇到占用就推迟打开词库。回归验证了同一文件锁下 CURRENT 保持原样，释放后能正常启动并提交候选。[升级回归](../../tests/rime_session_test.cpp)
