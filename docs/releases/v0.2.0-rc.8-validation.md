# v0.2.0-rc.8 验证记录

在 Windows x64 上用 MinGW-w64 和静态 librime 构建。五组 CTest 回归全部通过，覆盖单元测试、引擎 IPC、Windows TSF 文本宿主、候选浮层和模型子进程。单元测试共 96 项，最终的 TSF 宿主核对了 168 项行为。

## 键盘标点

| 场景 | 实际结果 |
| --- | --- |
| 中文模式下按 Shift + 减号，再按 Shift + 6 | 文档依次写入 `——……`，输入模式仍是中文 |
| 拼音候选显示时按减号、等号 | 候选可向前、向后翻页 |
| 输入 `nihao`，直接按 Shift + 减号 | 写入 `你好——` |
| 输入 `nihao`，按 Ctrl + .，再按 Shift + 减号 | 写入 `你好_`，任务栏仍显示「中」，悬停提示显示「英文标点」 |
| 切到「A」后按 Shift + 减号、Shift + 6、句号、Ctrl + . | 四个按键都交回应用处理 |
| 切回「中」，再次切换标点 | 可恢复中文句号。暂停学习后同样可以切换标点 |
| 在中文模式输入小数，再输入句末标点 | 可以打出 `3.14`，退格删除末尾新打的小数点并重按句号键后，得到 `3.14。` |

修复前，在真实 Rime 中按 Shift + 减号得到 `_`。旧版 Windows 输入宿主也复现了这个问题。使用保留有旧标点表的隔离缓存启动新版后，普通和暂停学习两套方案都重新生成了破折号映射。逐文件复核了产品 Rime 清单中的 19 项 SHA-256。

使用本地 Markdown 渲染器验证了 `——文字——` 显示为普通文字、`_文字_` 显示为强调。当前 Codex 窗口中的实体键盘输入仍待现场验证。

## 设置、词库与手动停录

- 钛银、极昼和深空各通过 130 项原生窗口检查。覆盖六页设置、字体、缩放、键盘导航、候选条、快捷键和预览编辑器。
- 引擎从隐藏启动状态打开设置后，已核对顶层窗口和模型页实际可见。测试了断开麦克风、词库读取失败、词语末页删除、撤销冲突和模型任务反馈。
- 将个人词表替换为同时间戳的新文件，旧实现会继续显示已删除的词条。修复后同时间戳、同大小的改名，以及后续删除均能在下一次拼音组合生效。
- 手动停录用隔离采音测试验证了低音量、静音、10 分钟上限和分两次确认。[停录回归记录](https://github.com/code-lawyer/simple-voice/blob/v0.2.0-rc.8/docs/releases/v0.2.0-rc.7-validation.md)

高对比度与 DPI 变化采用原生窗口测试分支。跨屏切换、现实设备热插拔、Windows 讲述人和长段真人听写仍待人工验收。
